SQL — език за работа с релационни бази данни

Този материал представя основните SQL команди, тяхното предназначение и синтаксис. Примерите използват същата учебна база данни, която студентите ще използват в практическата лаборатория.

11 темиПримери със Stoka, Klient и PorachkaНачално до напреднало ниво
01

Въведение в SQL

Как общуваме с релационната база данни?

SQL (Structured Query Language) е декларативен език за дефиниране, извличане и промяна на данни в релационни бази данни. Вместо да описваме стъпка по стъпка как да намерим даден запис, задаваме какъв резултат искаме да получим.

Основна идея

Данните се съхраняват в таблици. Таблицата се състои от колони (атрибути) и редове (записи). Връзките между таблиците се реализират чрез първични и външни ключове.

Учебна база данни

ТаблицаПредназначениеОсновни колони
StokaСтоки в каталогаid, name, price, vid_id
VidStokaКатегории стокиid, name
KlientКлиентиid, name
PorachkaПоръчкиid, klient_id, data
PorachkaStokaСтоки в поръчкитеporachka_id, stoka_id, kolichestvo

Например Stoka.vid_id е външен ключ към VidStoka.id. Така всяка стока може да бъде свързана със своята категория.

Основни групи SQL команди

  • DQL — извличане на данни: SELECT.
  • DML — манипулиране на данни: INSERT, UPDATE, DELETE.
  • DDL — дефиниране на структура: CREATE, ALTER, DROP.
02

SELECT — извличане на данни

Избираме кои колони и записи да бъдат показани.

Командата SELECT извлича данни от една или повече таблици, без да променя съхранената информация.

Основен синтаксис

SELECT column1, column2
FROM table_name;

Примери

Извеждане на една колона
SELECT name
FROM Stoka;

Връща имената на всички стоки.

Извеждане на няколко колони
SELECT name, price
FROM Stoka;

Връща името и цената на всяка стока.

Извеждане на всички колони
SELECT *
FROM Stoka;

Звездичката * означава всички колони. В реални приложения е по-добре да се посочват конкретните колони, когато са известни.

Псевдоним и изчисление
SELECT name,
       price * 1.20 AS price_with_vat
FROM Stoka;

AS задава псевдоним на колона. Изразите могат да извършват аритметични операции.

Важно: SQL не гарантира реда на резултатите, ако не използваме ORDER BY.
03

WHERE — филтриране на записи

Ограничаваме резултата според зададено условие.

Клаузата WHERE определя кои редове да участват в резултата. Условието се проверява за всеки запис.

SELECT name, price
FROM Stoka
WHERE price > 40;

Оператори за сравнение

ОператорЗначениеПример
=равноprice = 25
<> или !=различноprice <> 25
>, <по-голямо, по-малкоprice > 40
>=, <=по-голямо/равно, по-малко/равноprice <= 100

Логически оператори и специални условия

-- Две условия трябва да са изпълнени
SELECT name, price
FROM Stoka
WHERE price >= 20 AND price <= 50;

-- Едно от условията трябва да е изпълнено
SELECT name
FROM Stoka
WHERE price < 30 OR price > 300;

-- Диапазон от стойности
SELECT name
FROM Stoka
WHERE price BETWEEN 20 AND 100;

-- Списък от възможни стойности
SELECT name
FROM Stoka
WHERE vid_id IN (1, 2);

-- Търсене по шаблон: започва с М
SELECT name
FROM Stoka
WHERE name LIKE 'М%';

При LIKE символът % замества произволен брой символи, а _ замества точно един символ.

Често срещана грешка: текстовите стойности се ограждат с единични кавички, например name = 'Мишка'. Числовите стойности обикновено се записват без кавички.
04

UPDATE — промяна на съществуващи данни

Актуализиране на стойности в един или повече записи.

Командата UPDATE променя стойностите на избрани колони в съществуващи редове. Клаузата WHERE определя кои записи ще бъдат засегнати.

UPDATE table_name
SET column1 = value1,
    column2 = value2
WHERE condition;

Пример: промяна на цената на една стока

UPDATE Stoka
SET price = 50
WHERE id = 1;

-- Проверка на промяната
SELECT id, name, price
FROM Stoka
WHERE id = 1;

Пример: увеличение на цените с 10%

UPDATE Stoka
SET price = price * 1.10
WHERE vid_id = 2;

-- Проверка на засегнатите записи
SELECT id, name, price
FROM Stoka
WHERE vid_id = 2;
Внимание: ако пропуснем WHERE, командата ще промени стойността за всички редове в таблицата. Преди изпълнение на UPDATE е добра практика първо да проверим условието със SELECT.
-- Първо виж кои редове ще бъдат променени
SELECT *
FROM Stoka
WHERE id = 1;
05

DELETE — изтриване на записи

Премахване на редове от таблица.

Командата DELETE изтрива редове от таблица. Тя не премахва самата таблица или нейната структура.

DELETE FROM table_name
WHERE condition;

Пример: изтриване на една стока

DELETE FROM Stoka
WHERE id = 4;

-- Проверка: записът вече не трябва да присъства
SELECT id, name, price
FROM Stoka
ORDER BY id;

Пример: изтриване по условие

DELETE FROM Stoka
WHERE price < 20;

-- Проверка на останалите записи
SELECT id, name, price
FROM Stoka
ORDER BY id;
Внимание: DELETE FROM Stoka; без WHERE изтрива всички редове от таблицата. Проверявайте предварително кои записи ще бъдат засегнати чрез съответния SELECT.

06

ORDER BY и DISTINCT

Подреждане и премахване на дублиращи се резултати.

ORDER BY

ORDER BY подрежда резултатните редове по една или повече колони.

-- Възходящ ред (ASC е по подразбиране)
SELECT name, price
FROM Stoka
ORDER BY price ASC;

-- Низходящ ред
SELECT name, price
FROM Stoka
ORDER BY price DESC;

-- Два критерия
SELECT name, vid_id, price
FROM Stoka
ORDER BY vid_id ASC, price DESC;

ASC означава възходящ ред, а DESC — низходящ. При няколко критерия първо се прилага първата колона, а след това следващата за равните стойности.

DISTINCT

DISTINCT премахва повторенията в резултата. Уникалността се определя за цялата комбинация от избрани колони.

-- Уникални категории
SELECT DISTINCT vid_id
FROM Stoka;

-- Уникални комбинации категория и цена
SELECT DISTINCT vid_id, price
FROM Stoka;
07

JOIN — свързване на таблици

Извличане на свързани данни от повече от една таблица.

В релационните бази данни информацията често е разделена между няколко таблици. Чрез JOIN комбинираме редове, които имат свързани стойности в ключовите колони.

INNER JOIN

Връща само редовете, за които има съвпадение и в двете таблици.

SELECT Stoka.name, VidStoka.name AS vid
FROM Stoka
INNER JOIN VidStoka
  ON Stoka.vid_id = VidStoka.id;

LEFT JOIN

Връща всички редове от лявата таблица и съвпадащите от дясната. Когато няма съвпадение, колоните от дясната таблица съдържат NULL.

SELECT Klient.name, Porachka.id AS porachka_id
FROM Klient
LEFT JOIN Porachka
  ON Klient.id = Porachka.klient_id;
Ключов момент: условието след ON описва как се свързват таблиците. То не е същото като WHERE, което филтрира получения резултат.
08

Агрегатни функции

Изчисляване на обобщени стойности.

Агрегатните функции обработват множество редове и връщат една обобщена стойност.

ФункцияПредназначение
COUNT()Брои редове или ненулеви стойности.
SUM()Изчислява сума.
AVG()Изчислява средна аритметична стойност.
MIN()Намира минимална стойност.
MAX()Намира максимална стойност.
-- Брой на всички стоки
SELECT COUNT(*) AS broi
FROM Stoka;

-- Обща стойност на цените
SELECT SUM(price) AS total_price
FROM Stoka;

-- Средна, минимална и максимална цена
SELECT AVG(price) AS avg_price,
       MIN(price) AS min_price,
       MAX(price) AS max_price
FROM Stoka;

COUNT(*) брои редовете. COUNT(column) брои само стойностите, които не са NULL.

09

GROUP BY и HAVING

Групиране и филтриране на обобщени резултати.

GROUP BY обединява редовете с еднаква стойност в посочените колони. След това агрегатните функции могат да изчисляват стойности за всяка група.

-- Брой стоки във всеки вид
SELECT vid_id, COUNT(*) AS broi
FROM Stoka
GROUP BY vid_id;

-- Средна цена по вид
SELECT vid_id, AVG(price) AS avg_price
FROM Stoka
GROUP BY vid_id;

WHERE срещу HAVING

  • WHERE филтрира отделните редове преди групирането.
  • HAVING филтрира групите след групирането.
-- Показва само видовете с повече от една стока
SELECT vid_id, COUNT(*) AS broi
FROM Stoka
GROUP BY vid_id
HAVING COUNT(*) > 1;
Запомни: условие върху обикновена колона обикновено се поставя в WHERE, а условие върху резултат от агрегатна функция — в HAVING.
10

Подзаявки и CASE

По-сложни условия и изчисляване на категории.

Подзаявки (Subqueries)

Подзаявката е SQL заявка, вложена в друга заявка. Резултатът ѝ се използва от външната заявка.

-- Стоки с цена над средната цена
SELECT name, price
FROM Stoka
WHERE price > (
  SELECT AVG(price)
  FROM Stoka
);

CASE

CASE реализира условна логика в рамките на SQL заявка. Връща различна стойност според това кое условие е изпълнено.

SELECT name,
       CASE
         WHEN price > 100 THEN 'Скъпа'
         ELSE 'Достъпна'
       END AS category_price
FROM Stoka;
11

Практически правила и често срещани грешки

Как да пишем по-надеждни SQL заявки.

  1. Първо разбери условието. Определи кои колони трябва да се покажат и кои записи трябва да бъдат засегнати.
  2. Провери структурата. Увери се, че използваш правилните имена на таблици и колони.
  3. При UPDATE и DELETE първо пусни SELECT. Използвай същото условие в WHERE, за да видиш кои редове ще бъдат променени или изтрити.
  4. Проверявай резултата. След промяна на данните изпълни SELECT, за да потвърдиш ефекта.
  5. Използвай ясни имена и псевдоними. Това прави заявките по-лесни за четене.

Чести грешки

  • Липсваща или неправилна клауза WHERE.
  • Грешно име на колона или таблица.
  • Използване на = NULL вместо IS NULL.
  • Липсващо условие за свързване след JOIN.
  • Използване на агрегатна функция в WHERE вместо HAVING.
  • Очакване на определен ред на резултатите без ORDER BY.
-- Проверка за липсваща стойност
SELECT *
FROM Porachka
WHERE data IS NULL;
